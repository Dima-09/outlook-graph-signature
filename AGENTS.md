Язык общения, планов и отчётов — русский. Сохранять англоязычные идентификаторы, текст подписи и стиль исходников. Назначение и команды описаны в [README.md](README.md), устройство приложения — в [ARCHITECTURE.md](ARCHITECTURE.md), внешняя инфраструктура и выпуск — в [DEPLOYMENT.md](DEPLOYMENT.md).

## До изменений

- Прочитать архитектуру, сверить документы с фактическим кодом, проверить ветку, статус и локальные изменения. Сообщить о расхождениях владельцу.
- Представить план со списком создаваемых, изменяемых, перемещаемых и удаляемых файлов. Начать реализацию после одобрения. Перед удалением проверить прямые и косвенные зависимости.
- Работать в пределах открытого репозитория. Сохранять чужие изменения. Для сети и установки зависимостей использовать разрешения среды.
- Индекс, коммиты, push, теги, ветки и историю менять только по явному указанию. Деструктивные команды Git требуют отдельного разрешения.

## Границы проекта

- Одна постоянная ветка `main`, общие исходники и XML-шаблон. DEV и PROD задаются конфигурациями. Каждая сборка заменяет только свой каталог внутри `dist/`. Файлы в нём генерируются сборщиком.
- GitHub хранит исходники. Комплекты размещаются вручную в отдельных Cloudflare Workers Static Assets. Сборка и тесты выполняются локально. Изменения Cloudflare, Entra и Microsoft 365, подключение автоматизации и публикация требуют отдельного задания.
- Сохранять независимость сборки от хостинга, флаг `configured`, проверки конфигурации, целостность предыдущего результата при ошибках и отдельные самодостаточные бандлы runtime и Sign in.
- Изменять бизнес-логику, поля Graph, разрешения, обработку ошибок, авторизацию, события, совместимость и интерфейс только по отдельному заданию. Согласовывать новые зависимости, сервисы и архитектурные изменения.
- Client ID и Tenant ID публичны. Использовать публичный клиент без Client Secret. Хранить реальные профили сотрудников, токены и учётные данные вне тестов, файлов проекта и отчётов. Не подменять отсутствующие параметры вымышленными рабочими значениями.

## Приёмка

- Для приложения или сборки выполнить тесты и обе реальные компиляции. Проверить независимость выходных каталогов, XML, конфигурацию в бандлах, отсутствие дополнительных JS-чанков, ссылки HTML и точный URL в корневом `.well-known`.
- Использовать фиктивные профили. Проверки Entra, Graph и установки в Classic, New, Web и Mobile Outlook учитывать отдельно от локальных проверок.
- Для изменений только в документации проверить факты, ссылки и diff. Сборки и тесты, создающие файлы вне объёма такой задачи, пропустить.
- В отчёте привести изменения и причины удалений, команды, результаты, ограничения и ручные действия владельца. Показать Git status и краткий diff. Commit, push и deploy выполнять только по отдельному указанию.
